## 🛠 المواصفات التقنية والملفات

الموقع مصمم ومطور بالكامل باستخدام:
- **HTML5 الدلالي (Semantic HTML5)** لدعم محركات البحث (SEO) وقارئات الشاشة.
- **CSS3 الحديث** بنظام تصميم قياسي ومتغيرات ألوان (CSS Variables) ودعم تام للاتجاه من اليمين لليسار (`dir="rtl"`).
- **Vanilla JavaScript (ES6+)** خالص، بدون أي مكتبات خارجية ثقيلة (لا React، لا Tailwind، لا Bootstrap، لا jQuery).
- **لا يتطلب أي أدوات بناء (No Build Tools)** — جاهز للتشغيل مباشرة على أي استضافة ثابتة أو خادم ويب.

### هيكل الملفات والمجلدات:
```text
DR-Yassmin Websie V.01/
├── index.html               # الصفحة الرئيسية والهيكل الكامل للعلامة الطبية
```

## ⚙ دليل تعديل المحتوى والإعدادات (`js/config.js`)

كافة البيانات الطبية وساعات العمل وأرقام التواصل مجمعة في ملف مركزي واحد: `js/config.js`.

### 1. تعديل مواعيد العمل وساعات العيادات:
بمجرد تأكيد جدول المواعيد الرسمي من إدارة العيادة لكل فرع، يمكن تعديل الحالة من `pending_verification` إلى `active` وكتابة المواعيد:
```javascript
// داخل كائن branches:
mubtadiyan: {
  scheduleStatus: "active", // تغيير الحالة
  schedule: {
    hoursText: "السبت والاثنين والأربعاء من 6:00 م حتى 9:00 م",
    workingHours: {
      start: "18:00",
      end: "21:00"
    }
  }
}
```

### 2. تفعيل رقم واتساب المعتمد للحجز المباشر:
إذا رغبت العيادة في استقبال طلبات الحجز مباشرة عبر واتساب:
```javascript
booking: {
  whatsappEnabled: true,
  whatsappNumber: "2010XXXXXXXX" // كتابة الرقم بالصيغة الدولية بدون + أو مسافات
}
```

### 3. تأكيد أرقام الهواتف الرسمية:
بعد التأكيد الرسمي لأرقام الهواتف من إدارة الفرعين، يتم تغيير `phoneVerified` إلى `true` لتفعيل الاتصال المباشر بضغطة واحدة:
```javascript
mubtadiyan: {
  phone: "01223939081",
  phoneVerified: true // عند التحقق
}
```

### 4. تعديل الخدمات والأسعار:
قائمة `SITE_CONFIG.services` تحتوي على كافة التخصصات، ويمكن إضافة رسوم الكشف عند تأكيدها بإضافة حقل `fee: "XXX ج.م"` إلى كل خدمة.

## 📅 آلية عمل حجز المواعيد (Request Workflow)

الموقع صُمم ليعمل بنزاهة وشفافية كاملة وفق المعايير الطبية:
1. **الخطوة 1: اختيار الخدمة** (كشف نساء وتوليد، متابعة حمل، تأخر إنجاب، استشارة).
2. **الخطوة 2: اختيار الفرع** (المبتديان - السيدة زينب أو الدقي - الكوثر كلينيك).
3. **الخطوة 3: تحديد التاريخ والفترة المفضلة** (التقويم يمنع اختيار تواريخ سابقة ويوضح أن الفترة المختارة هي وقت مفضل للزيارة وليست حجزاً إلكترونياً مؤكداً فورياً).
4. **الخطوة 4: بيانات التواصل** (الاسم ورقم الموبايل المصري مع التحقق البرمجي التام وموافقة الخصوصية).
5. **الخطوة 5: مراجعة الطلب**.
6. **الخطوة 6: تجهيز الطلب (Request Prepared)**:
   - يظهر للمريضة ملخص الطلب جاهزاً.
   - إذا تم تفعيل الواتساب، يُفتح رابط واتساب رسمي بالنص المنظم بالكامل.
   - زر مدمج لنسخ نص الطلب للحافظة بضغطة زر مع إشعار مرئي.
   - رابط مباشر لصفحة الحجز على فيزيتا كقناة موثقة بديلة.
   - **تأكيد مهم:** الموقع يوضح صراحة أن هذا طلب موعد ولا يعتبر حجزاً مؤكداً إلا بعد مراجعة العيادة للمواعيد والتواصل مع المريضة هاتفياً.

## 🚀 خطوات النشر والاستضافة (Deployment Guide)

الموقع موقع ثابت (Static Website) لا يتطلب بيئة تشغيل خاصة (No Node.js / No PHP runtime required):

### الاستضافة على GitHub Pages:
1. رفع محتويات المجلد إلى مستودع GitHub.
2. الدخول إلى `Settings` -> `Pages`.
3. اختيار فرع `main` والمجلد `/root` والضغط على `Save`.

### الاستضافة على Netlify أو Vercel:
- سحب المجلد مباشرة (Drag & Drop) إلى لوحة التحكم ليتم نشره في ثوانٍ مع شهادة SSL مجانية.

### الاستضافة على cPanel / خوادم مشتركة:
- رفع محتويات المجلد مباشرة إلى مسار `public_html`.

## 🔌 التكامل المستقبلي مع نظام خلفي (Backend API Ready)

تم تجهيز ملف `js/main.js` بمحول برمجي جاهز (`BookingBackendAdapter`):
```javascript
const BookingBackendAdapter = {
  submitRequest: async function (bookingPayload) {
    if (!SITE_CONFIG.apiBackend.enabled) {
      console.info('[Booking Backend Adapter] Request prepared locally:', bookingPayload);
      return { status: "prepared_locally" };
    }
    // عند تفعيل الباك إند: يتم إرسال طلب POST آمن إلى الخادم
    return await fetch(`${SITE_CONFIG.apiBackend.baseUrl}${SITE_CONFIG.apiBackend.endpoints.createRequest}`, {
      method: 'POST',
      headers: SITE_CONFIG.apiBackend.headers,
      body: JSON.stringify(bookingPayload)
    });
  }
};
```
لتفعيل الربط البرمجي الكامل مستقبلاً، يكفي تعديل حقل `apiBackend.enabled` إلى `true` وضبط مسار الخادم في `js/config.js`.
